# janrakshak_user

A new Flutter project.

## Navigation and offline maps

**Trip planner.** Pick From and To, then *Check route & navigate*. The route comes from OSRM
(`router.project-osrm.org`, the public demo server; self-host OSRM for production), is checked against active
hazards (diverted if needed), and opens turn-by-turn navigation: next maneuver and distance, remaining distance,
ETA, and an automatic reroute (through the same hazard check) after three GPS fixes more than 60 m off the route.

**Offline map.** Once both endpoints are chosen, *Download map to destination* copies the map tiles along the route
(zoom 5 up to 12, one tile of buffer; a very long trip gets a shallower zoom to stay under ~10,000 tiles, ~160 MB)
onto the phone. Saved tiles are used first on every map screen, so the map keeps working without signal.

### Self-hosted basemap (no third-party tile service)

The map is one file, `north-eastern-zone.pmtiles`: OpenStreetMap data (Geofabrik extract) cut into vector tiles by
[Planetiler](https://github.com/onthegomap/planetiler) (OpenMapTiles schema), hosted as a static object in the
Supabase `basemap` bucket. The app reads it with HTTP range requests, so there is no tile server to run, and
downloading tiles for offline use is allowed because it is your data.

```
tools/basemap/build.sh     # download the extract + build out/north-eastern-zone.pmtiles (~3 min, needs Java 21+)
tools/basemap/upload.sh    # upload it and check the public URL answers range requests
```
`upload.sh` reads `SUPABASE_SERVICE_ROLE_KEY` from `tools/basemap/.env.local` (git-ignored; Dashboard > Project
Settings > API). Never put that key in a script or commit it: it bypasses all row-level security.

* **Where the app looks:** `PMTILES_URL`, which defaults to
  `https://sjcqwxthimfuxmrodsbs.supabase.co/storage/v1/object/public/basemap/north-eastern-zone.pmtiles`.
  Override with `--dart-define=PMTILES_URL=...` (see `tiles.example.json`). Until the file exists the app shows the
  OpenStreetMap raster map and the download card says offline maps are not set up. Once uploaded, no app update is needed.
* **Size vs detail:** `MAXZOOM` (default 12, ~30 MB: fits the 50 MB upload limit of the free plan, which is what is
  hosted today). `MAXZOOM=13` is ~58 MB and `MAXZOOM=14` ~125 MB and need a paid plan with a higher upload limit
  (Dashboard > Storage > Settings). Build the app with the same value (`--dart-define=PMTILES_MAX_ZOOM=13`). The map
  overzooms past the stored level, so roads stay sharp; only the finest road and building detail is lost.
* **Other regions:** `EXTRACT=asia/india/eastern-zone-latest tools/basemap/build.sh` (any Geofabrik path; whole India
  is ~1.3 GB of input and needs more disk and RAM).
* **Style:** `assets/basemap/style.json` is generated by `tools/basemap/make_style.py` (OpenMapTiles *Dark Matter*,
  retinted to the app palette). Only these layers are built into the file: aeroway, boundary, building, landcover,
  landuse, place, transportation, transportation_name, water, water_name, waterway. Add POIs (hospitals,
  shelters) by adding `poi` to `LAYERS` in `build.sh` and a layer to the style.
* **Attribution:** "OpenMapTiles © OpenStreetMap contributors" is shown on the map (ODbL / CC-BY requirement).
* **India boundaries:** the extract carries OpenStreetMap's own boundary lines. Replace the `boundary` layer with
  Survey of India data before public release if your legal review requires the official depiction.
* **Cost:** the file is public, so every map view uses your Supabase storage egress.
